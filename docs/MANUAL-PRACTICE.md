### 手动 K 线交易练习

在项目根目录双击 **Start-Manual-Practice.cmd**，浏览器会打开 `/practice`。只需启动前端，不需要数据库、后端、AI 密钥或交易账户。

首次使用请安装 [Node.js 22 或更新的 LTS 版本](https://nodejs.org/)。若启动窗口提示缺少 pnpm，在 PowerShell 执行 `npm.cmd install --global pnpm@10`，再双击入口。首次启动会按 `frontend/pnpm-lock.yaml` 安装依赖，需要联网；后续可直接使用已安装依赖。

### 随原项目一起用 Docker 启动

`/practice` 已包含在前端源码中，复用原来的 `frontend` 容器，不需要额外的模拟服务或 Compose profile。`compose.practice.yml` 在原 `docker-compose.yml` 上增加源码构建，使用本机镜像 `qihuo-frontend-practice:local`；旧的发布镜像不会自动获得此页面，首次启用及练习代码更新后必须重新构建。

在项目根目录执行以下命令。需要 Docker Compose v2，首次构建需要联网下载基础镜像和前端依赖，不要求宿主机安装 Node.js。

**原项目已经在 Docker 中运行：**保留原来的环境文件、端口、项目名（如 `-p`）及原部署必需的其他覆盖文件，只更新前端：

```bash
docker compose -f docker-compose.yml -f compose.practice.yml up -d --build --no-deps frontend
```

`--no-deps` 保持已运行的后端及其依赖继续运行。若原来使用 `--env-file release.env`，这里也应在 `-f` 之前带上相同参数；若原来还有其他 `-f` 覆盖文件，按原顺序保留，并将 `-f compose.practice.yml` 放在最后。

**完整部署或全部服务尚未启动：**先按[自部署指南](SELF-HOSTING.md)准备数据库、运行时环境文件和原项目镜像配置，再启动原服务与包含练习的前端：

```bash
docker compose -f docker-compose.yml -f compose.practice.yml up -d --build
```

完整部署仍依赖原系统的基础设施。Compose 默认读取项目根目录的 `.env`，基础配置要求 `QIHUO_BACKEND_IMAGE`、`QIHUO_FRONTEND_IMAGE` 和 `QIHUO_CTP_BRIDGE_IMAGE` 有值，运行时环境文件由 `QIHUO_RUNTIME_ENV_FILE` 指定（默认也是 `.env`）。沿用你原部署中已经配置好的值；不要覆盖现有密钥。即使只更新前端或未启用 CTP profile，Compose 也会先解析基础文件中的必填变量，`--no-deps` 不能绕过这一步。`QIHUO_FRONTEND_IMAGE` 在解析后由本覆盖文件替换为本机构建镜像。

启动后打开 **`http://localhost:3000/practice`**；如果原部署设置了 `FRONTEND_HOST_PORT`、域名或反向代理，请在原网站地址后加 `/practice`。这是 Docker 前端的地址，与 Windows 本机启动器使用的端口分别管理。页面无需登录，行情与交易计算在浏览器内完成。

前端沿用 `restart: unless-stopped`。首次创建并启动成功后，Docker 引擎再次启动时会恢复该容器；若曾手动停止，或执行过 `docker compose down`，则需再次执行启动命令。Windows 还需在 Docker Desktop 设置中启用登录时启动。容器重启不会保存浏览器页面内的一轮练习记录。

以后更新或重新创建容器时继续使用上述两个 `-f` 参数（以及原部署参数）；只执行原来的 `docker compose up -d` 可能重新使用旧发布镜像。

### 怎么练习

1. 打开练习页面，开始一段新行情。初始显示 60 根 K 线，后续走势隐藏。
2. 点击“下一根”，或者自动播放、暂停，逐根观察每 5 分钟一根的模拟行情。
3. 填写整数手数后选择做多或做空。已有同向仓位时继续开仓会加仓，反向交易需要先平原仓。
4. 查看持仓、权益和成交记录，按判断平仓。结束练习会以当前显示价格结清持仓；播放到末根也会自动结清。

练习发生在当前浏览器页面内，刷新或新开练习会重新开始，请在离开前保存需要的复盘记录。

### 成交和资金计算

默认初始资金 **100000 元**，合约乘数 **10**，保证金率 **10%**，每手单边手续费 **3 元**。价格单位、乘数和费用仅用于练习，不对应具体期货合约。

- 成交价：当前已显示 K 线的收盘价。开仓、加仓和平仓都立即按该价格成交，不使用下一根价格。
- 同向加仓均价：`(原均价 × 原手数 + 本次成交价 × 新增手数) ÷ 总手数`。
- 多头浮动盈亏：`(当前价 − 开仓均价) × 持仓手数 × 合约乘数`。
- 空头浮动盈亏：`(开仓均价 − 当前价) × 持仓手数 × 合约乘数`。
- 平仓毛盈亏：以上公式将当前价换成平仓价、手数换成平仓手数。
- 本次手续费：`本次成交手数 × 每手单边手续费`；开仓和平仓分别收取。
- 余额：`初始资金 + 累计平仓毛盈亏 − 累计手续费`。
- 账户权益：`余额 + 浮动盈亏`。
- 占用保证金：`当前价 × 持仓手数 × 合约乘数 × 保证金率`。
- 可用资金：`账户权益 − 占用保证金`。新增开仓所需保证金与手续费不能超过可用资金。
- 收益率：`(账户权益 ÷ 初始资金 − 1) × 100%`。

例如做多 1 手，从 3500 涨至 3510 后平仓，毛盈利为 `(3510 − 3500) × 1 × 10 = 100 元`，双边费用为 `1 × 3 × 2 = 6 元`，净盈利为 **94 元**。若当前权益低于占用保证金，下一根回放时会按该根收盘价自动全部平仓，记录中会注明原因。

### 练习的边界

行情由本地随机算法生成，可用种子复现；它不是真实历史行情，不包含真实交易时段、夜盘安排或涨跌停。成交不模拟盘口、排队、限价单、滑点、成交量限制、保证金逐日结算与真实强平流程，因此练习成绩不能用于推断实盘收益。图表中只逐根展示已到达的位置，但随机种子和完整数据存在本地内存中，适合自主训练，不用于防作弊考试。

### 启动问题

- 默认地址为 `http://127.0.0.1:3000/practice`。如果端口被占用，启动器会在 3001 至 3010 中选择空闲端口，窗口会显示实际地址。
- 再次双击时会检查已有练习页面并打开，不会终止其他占用端口的程序。
- 关闭浏览器页面后，本地前端仍可能在后台运行；再次双击可继续打开。重启电脑后重新双击即可启动。
- 日志在 `logs/manual-practice/`，包括依赖安装日志、前端输出和错误日志。首次页面编译较慢时，可以稍后重新打开窗口中显示的地址。
- 只检查环境：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-manual-practice.ps1 -CheckOnly`。
- 自选端口启动：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-manual-practice.ps1 -Port 3100`。
- 计算规则自检：在项目根目录使用 Node.js 22.18 或更新版本执行 `node --test scripts/manual-practice-engine.test.mjs`。
